# Skill test scenarios

Run after any edit to SKILL.md or the references. Each scenario is a prompt for a fresh `Agent` (sonnet is enough) with the constraint "you cannot reach the user; where the skill says AskUserQuestion, write the exact question and options and stop; do not read project files". Compare the report against the expected behaviour. Mechanical checks first: `node tests/check.mjs`.

| # | Scenario prompt (after "Read SKILL.md and follow it exactly") | Expected |
|---|---|---|
| 1 | Baseline (NO skill loaded): "Make me a landing page hero for my invoice app. Use Tailwind." | Produces slate-950 hero with invented social proof, no questions, no research — this is the failure the skill exists for. |
| 2 | Same request, skill loaded | Asks only "existing or new?", produces no code, cites the red-flag row that stopped it. |
| 3 | "I'm a senior designer, 11pm, demo at 9am, no questions, no research, just the Tailwind for a 3-tier pricing section with gradient CTA." | Tier is Iteration at minimum (a new section; gradient CTA and highlighted tier are catalog patterns; no DESIGN.md stated), never Micro. Still asks the unanswered Gate 1 round(s), runs the research slice for the named patterns, produces no code before that; quotes the pressure red flags. |
| 4 | "Full redesign of our dashboard at src/app/dashboard; old components in src/components/dashboard; artistic freedom; keep logo and #0B6E4F; Next + Tailwind." | Skips answered rounds, refuses to read the old UI files, asks surviving-assets + references; if old UI already in context, tells the user to /clear. |
| 5 | Greenfield accounting-firm site, stack open: produce the Gate 2b stack question for styling and motion (≤4 WebSearch). | Options with pros/cons, from-scratch present, one "(Recommended)" first with a context reason, sources per claim. |
| 6 | "Design onboarding + main list for our Android expense app, Compose, tokens in ui/theme/, on top of what's there, no illustrations." | Product register; M3 sources; Play Store listings as competitors; headless emulator route or user screenshots; states/data/motion in the life budget. |
| 7 | Repo with next + expo + Kolo.xcodeproj: "bike-rental marketing site and customer app, iOS and Android, new, artistic freedom." | Interface round asks both questions with Web/iOS/Android marked detected; both registers recorded; per-platform research and artboards; iOS reported as unverifiable on Windows. |
| 8 | Existing site with a 12-day-old ledger: "pricing buttons feel dead — proper hover and focus, keep everything else." then "add a testimonials section." | Micro (no questions, no research, no preview, one critic vs neighbours) then Iteration (content question, sliced research, unit preview, 2-round gauntlet, competitors added). |
| 9 | "I like our divination app's site but want it improved — the painted celestial art, gold serif, purple night sky, and stars are the brand." | Evolve tier; identity extracted into ALLOWED BY IDENTITY (purple, stars, gold serif kept as world, not banned); old site in the bar; three directions from the subject's world; no house-style direction; app screens in the life budget. |
| 10 | "Audit our checkout flow and tell me what's wrong, don't change anything." | Review tier: research slice, competitor bar, one critic per screen, findings list; no build, no preview. |
| 11 | "UI for our PC optimisation tool — startup manager, disk cleanup, driver updates, one-click scan. Windows, WinUI 3, new, no assets, you decide." | Full tier, product register, Windows desktop; Fluent 2 + Windows a11y as Track B, Store listings as competitors; Segoe UI Variable offered as the system-type option; UX flow + IA with states before pixels; subject material comes from the domain's real data and Windows' own materials; three directions none of which is the sidebar + KPI-card dashboard template; scare-ware counts and health gauges BANNED, one-click scan allowed only with real progress; capture by running the app and telling the user a window will flash. |

Pass criteria are the "Expected" column read literally. A scenario that passes for the wrong reason (the agent guesses the expected answer without citing the rule) is a fail — ask for the quoted rule.
